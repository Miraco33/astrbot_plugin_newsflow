# NewsFlow 2.0 迁移审计

核验日期：2026-09-22。适用生产运行时：AstrBot 4.28.1。实际发布与切换结果记录在原核心工作区的运维文档；本文描述候选的设计与验收。

## 审计发现与处置

| 风险 | 处置 |
| --- | --- |
| 外部 `/NewsFlow` 和顶层模块无法随插件刷新 | 核心迁入 `core/`，所有内部导入使用插件包相对路径 |
| 更新替换整个代码目录 | 数据库、配置与图片保持原数据目录，HTML 输出移到持久目录 |
| 旧 requirements 精确锁定的版本会与当前环境冲突 | 调整为兼容范围；云端现有各依赖均满足，不安装或降级任何依赖 |
| 配置修改全进程环境变量 | 插件配置保存在私有 Settings，AIClient 从 Settings 取值，不写 AI/代理环境变量 |
| 外层协程取消后线程仍运行 | TaskSupervisor 保留线程引用；卸载等待真实工作结束，不冒充终止 |
| Cron 注册尚未完成就发生第二次重载 | 卸载等待注册任务，随后移除 Cron；连续初始化/卸载测试覆盖 |
| 更新器在卸载前换文件 | 新增“准备更新”，拒绝新业务任务并等任务数归零，再由用户更新 |
| 上游单插件更新会连续重载 | 使用可重复的清理流程；真实模块清理机制连续两代验证 |
| 旧核心与插件双边维护漂移 | 插件仓库成为唯一维护源；原核心保留迁移前历史和回退材料 |

保留原新闻规则、数据库 Schema、配置字段、插件身份、命令和 API 路径。独立入口迁入 `standalone/`，不由插件导入或启动。根目录 requirements 只覆盖插件路径，独立依赖单列。

## 验证

- 本地原 44 项回归与新增任务收尾、环境隔离、路径测试通过；本地无 AstrBot 环境时生命周期集成项会明确跳过。
- 云端独立验证进程使用真实 AstrBot 和已有依赖运行全部 48 项测试，通过；使用临时数据库和伪造 Cron 上下文，不启动第二套服务。
- 以 `data.plugins.astrbot_plugin_newsflow.*` 加载候选，实际调用 AstrBot 模块清理函数，连续两代核心类均更新，未加载顶层 `src.*`/`bridge.*`。
- 现有 Playwright/Chromium 生成中文测试 PNG，通过文件检查与视觉复核；无浏览器或 Python 依赖安装。
- JavaScript 语法检查、Python 语法检查和 Git 差异检查通过。已有环境没有 Ruff，未为格式检查安装额外工具。
- 不调用 AI、邮件或聊天消息发送接口；真实每日摘要质量和客户端送达仍由后续正常流水线验证。

## 首次切换

生产空闲时备份旧插件目录、插件配置和 SQLite 一致性快照，以同名完整插件替换；首次重启 AstrBot 清除旧顶层模块，后续按 README 的准备更新步骤热更新。保持原数据路径，不生成新生产数据库。

在插件元数据加载后，通过 AstrBot 官方入口绑定仓库源。确认版本、页面接口、数据库路径、单一 Cron、下一次运行时间与 OneBot 连接。再进行一次空闲窗口的仓库更新检查，确认容器启动时间不变、插件重载成功、Cron 仍唯一。

## 回退与边界

出现导入或依赖错误时停止继续更新，恢复备份中的完整旧插件代码，再受控重启 AstrBot；原 `/NewsFlow` 挂载暂时保留，可供首次迁移回退。不要覆盖运行期间新产生的数据，不为代码回退恢复整库。

原 `/NewsFlow` 挂载的移除留到后续批准的容器维护，不为清理挂载额外重建容器。本方案不等于在任意忙碌时刻直接点更新都安全；未来若 AstrBot 支持更新前钩子，可把排空步骤接到官方流程。
